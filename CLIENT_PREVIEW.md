# Клиентская демонстрация 4КРУГА

**Обновление:** публичный просмотр опубликован на https://loginnok.github.io/4kruga-client-preview/ без пароля по отдельному указанию владельца. Его режим и ограничения описаны в [GITHUB_PAGES.md](GITHUB_PAGES.md). Ниже описан отдельный серверный вариант CLIENT_PREVIEW для VPS, который пока не развёрнут; его Basic authentication не относится к GitHub Pages.

Подготовлено 1 ноября 2026. Владелец разрешил размещение последующим сообщением. Внешнее размещение пока не выполнено: SSH-вход на VPS отклоняется, временное подключение Cloudflare не установилось, автоматическая проверка отклонила запуск внешнего сервера с причиной blocked by policy. Действующий 4kruga.ru, DNS и существующие серверные приложения не изменялись.

## Локальный просмотр

Текущий клиентский режим: http://localhost:3000. После остановки — START_CLIENT_PREVIEW.bat или npm run preview. Сначала при необходимости запустите собственную PostgreSQL через npm run setup:local, затем npm run preview:setup и npm run build.

Обычный npm start сохраняет прежний режим разработки и рабочую kruga_shop с её локальными проверочными записями. Клиентский просмотр запускается отдельно, на kruga_shop_preview. Не запускайте оба режима на одном порту.

В preview импортирован снимок **41 реального товара и 67 отдельных фотографий** с 4kruga.ru: Xiaomi — 12, Kugoo — 12, Ninebot — 12, Dualtron — 5. Это проверенная выборка для демонстрации, не полная выгрузка всего ассортимента. Ссылки каждой карточки и исходного изображения записаны в prisma/official-catalog.json и CSV отчёта.

Фото: public/media/4kruga/*.webp. По последнему указанию владельца в интерфейс возвращён ранее согласованный знак варианта C — public/logo-transparent.svg. Он восстановлен из сохранённого файла без нового рисунка. Исходный public/logo.png и скачанный логотип действующего сайта public/media/4kruga/logo-original.png сохранены без изменений; последний в интерфейсе не используется. Исходные загруженные фотографии и страницы остаются приватно в .state/source-import. В браузере используются только локальные файлы, не hotlinks.

Страницы: главная и её категории/товары, /catalog, /product/4kruga-4034 и остальные 40 отдельных карточек. Режим показывает реальную цену и статус наличия источника. Точный складской остаток не опубликован: число штук не выдумывается. Код 4K-ID — внутренний указатель на ID карточки исходного каталога, не выданный за артикул производителя. Совместимые модели извлекаются только из явного названия товара; отсутствие точной модели показывается честно.

Внешние заказы, оплата и заявки отключены. Пользователь может читать товар и менять ракурс фото, фильтровать и искать. /cart, /checkout, /repair объясняют режим просмотра и не принимают персональные данные.

## Разделение и защита

- Рабочая БД kruga_shop не копируется в просмотр; её заказы, сессии и администратор сохранены.
- kruga_shop_preview содержит реальный каталог и **0 заказов, 0 заявок, 0 администраторов, 0 покупательских сессий**.
- Роль kruga_preview_read имеет только SELECT на пяти таблицах каталога и default_transaction_read_only=on. Административные таблицы ей недоступны.
- Сервер возвращает 404 для /admin, /api/admin, истории заказов и служебных API. Запросы изменения любых маршрутов получают 403/404. Скрытием ссылок защита не ограничивается.
- Для внешнего режима Basic authentication применяется к HTML, API и картинкам. Пароль не находится в frontend. Используется хеш случайного секрета высокой энтропии. HTTPS нужен обязательно: Basic нельзя передавать по публичному HTTP.
- Локально PREVIEW_LOCAL_OPEN=1 допустим только без публичного origin и при bind 127.0.0.1. Запросы с заголовками не настроенного reverse proxy отклоняются. При заданном PREVIEW_PUBLIC_ORIGIN HTTPS авторизация обязательна, даже если флаг local-open оставлен включённым.
- Внешний origin без HTTPS или без реквизитов доступа блокирует запуск. CLIENT_PREVIEW отказывается работать на БД с именем, отличным от kruga_shop_preview/kruga_shop_preview_test.
- Аналитики и сторонних изображений нет. Индексация запрещена через X-Robots-Tag. В конфигурации Nginx access log выключен; эксплуатационный error log всё равно требует согласованного хранения.

Локальные параметры доступа владельца находятся в .state/preview-access.txt, настройки — .env.preview.local. Не отправляйте эти файлы заказчику целиком. Существующий приватный репозиторий не обновлялся: эта задача не дала разрешения публиковать изменения.

## Обновление материалов

Импортер — scripts/import-official.py. Нужны Python 3 с Pillow и BeautifulSoup4; для этой работы использованы изолированные библиотеки в .state/import-libs, не глобальная установка. Исходные URL брендов зафиксированы по найденным ссылкам действующего каталога.

Для новой проверки источника используйте аргумент --refresh. Без него importer использует локальный кэш; дата каждого товара отражает время его загрузки. Не выдавайте повторную сборку из кэша за повторную проверку цен.

На текущем компьютере:

```powershell
& 'C:\Users\kiril\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' scripts/import-official.py --refresh
npm run preview:setup
npm run build
```

Перед новой клиентской демонстрацией проверьте изменения цены, соответствие картинок, дату снимка и не появились ли ошибки импорта. Реальная доступность товара может измениться после снимка каталога.

## Размещение по HTTPS после разрешения владельца

Ниже — инструкция для оператора размещения, не для заказчика. Не передавайте заказчику архив исходников, репозиторий, SSH, БД, env-файлы или админские реквизиты. Заказчик получает только HTTPS URL и отдельный пароль просмотра.

### 1. Выбрать отдельный hostname и подготовить TLS

Владелец должен разрешить размещение и назвать hostname. В шаблонах 4kruga-preview.example.com — **заменяемый пример, не опубликованная ссылка**. После разрешения создайте A-запись выбранного поддомена на разрешённый сервер и получите обычный доверенный TLS-сертификат. Не меняйте DNS 4kruga.ru. Не устанавливайте конфигурацию на существующий production без резервной копии и проверки конфликтов портов/vhost.

### 2. Разместить код отдельно

Нужны Node.js 24.x, PostgreSQL и Nginx. Папка /srv/4kruga-preview, отдельный системный пользователь fourkruga-preview без интерактивного входа. Перенесите текущий проверенный проект оператору, исключив .git, node_modules, dist, .state, .env*, все рабочие БД и отчёты с локальными реквизитами. .env.example и deploy/client-preview.env.example допустимы как пустые шаблоны. Старый GitHub commit не содержит текущих изменений — не используйте его вместо этой рабочей копии.

В этой папке:

```sh
npm ci
```

### 3. Создать новую БД и две роли

В локальной консоли PostgreSQL администратора:

```sql
CREATE ROLE kruga_preview_owner LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE kruga_preview_read LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE;
\password kruga_preview_owner
\password kruga_preview_read
CREATE DATABASE kruga_shop_preview OWNER kruga_preview_owner;
ALTER ROLE kruga_preview_read SET default_transaction_read_only=on;
```

Пароли задаёт оператор в интерактивной консоли, не в публичных командах. DATABASE_URL владельца только временно передайте процессу миграции через защищённый EnvironmentFile. В приватном /etc/4kruga-preview-owner.env должен быть только DATABASE_URL владельца новой БД. Этот файл не используется постоянной службой и не передаётся клиенту. Затем в папке проекта:

```sh
node --env-file=/etc/4kruga-preview-owner.env node_modules/prisma/build/index.js migrate deploy
node --env-file=/etc/4kruga-preview-owner.env --import tsx prisma/import-official.ts
npm run build
```

Подключитесь к новой kruga_shop_preview её владельцем и выдайте чтение:

```sql
GRANT USAGE ON SCHEMA public TO kruga_preview_read;
GRANT SELECT ON "Category","Brand","ScooterModel","Product","Compatibility" TO kruga_preview_read;
```

Не создавайте администраторов и не импортируйте orders, sessions, Admin или RepairRequest. Рабочая БД приложения здесь не используется.

### 4. Настроить внешний режим и пароль просмотра

Скопируйте deploy/client-preview.env.example в /etc/4kruga-preview.env с доступом только системному администратору и пользователю службы. Замените DATABASE_URL на роль **kruga_preview_read**, а PREVIEW_PUBLIC_ORIGIN на выбранный HTTPS origin. Оставьте PREVIEW_LOCAL_OPEN=0, HOST=127.0.0.1, PORT=3104.

Сгенерируйте отдельный случайный пароль не менее 24 случайных байт. В PREVIEW_PASSWORD_SHA256 запишите его SHA256; сам пароль передавайте клиенту отдельно от URL. Локальный настроенный случайный пароль можно взять владельцу из .state/preview-access.txt, но новые копии env должны содержать только хеш. Не используйте пароли от магазина, VPS или админки.

### 5. Запустить отдельную службу и HTTPS proxy

Установите deploy/4kruga-preview.service в /etc/systemd/system/. Проверьте абсолютный путь Node 24, пользователя и путь проекта. В Nginx-шаблоне замените hostname и пути TLS-сертификата. Проксируйте только к 127.0.0.1:3104; исходный код никогда не должен быть document root Nginx. Пароль проверяет приложение на каждом HTML/API/asset запросе.

После разрешения публикации и готовности сертификата:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now 4kruga-preview
sudo nginx -t
sudo systemctl reload nginx
```

### 6. Приёмка внешней ссылки перед отправкой клиенту

```sh
curl -I https://YOUR_HOST/
curl -u client https://YOUR_HOST/api/config
curl -u client https://YOUR_HOST/admin
curl -u client -X POST https://YOUR_HOST/api/orders
```

Первый запрос — 401 с WWW-Authenticate; curl -u client запросит пароль интерактивно. Конфигурация — 200 и clientPreview=true; админка — 404; POST заказа — 403. Отдельно проверьте отказ без пароля для реальной /media/4kruga/*.webp, корректный сертификат в браузере и 0 заказов/заявок после теста. Если что-то не проходит, клиентскую ссылку не передавайте.

После этого URL равен PREVIEW_PUBLIC_ORIGIN. Заказчику передайте только этот адрес и отдельный пароль. По окончании согласованного показа остановите службу и удалите её vhost из внешнего доступа; сроки хранения каталога и технических журналов согласуйте отдельно.

Неудачный Cloudflare tunnel остановлен; клиентская HTTPS-ссылка не объявляется работающей. Подготовлены конфигурации и серверные границы доступа. Мобильная приёмка выполнена в браузерных viewport, не на физическом телефоне.
