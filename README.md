# 4 круга — каталог и локальный интернет-магазин

**Сайт GitHub Pages:** https://loginnok.github.io/4kruga-client-preview/ — публичный просмотр, поиск и фильтры без оформления заказов. [Как устроена публикация](GITHUB_PAGES.md).

Работающее приложение на основе существующего варианта C. Сохранены светлая основная часть, синий акцент, тёмно-синяя шапка/футер и исходный логотип. Действующий 4kruga.ru не изменён.

## Актуальный клиентский просмотр — 1 ноября 2026

Реальные товары и фотографии импортированы с 4kruga.ru. По последнему указанию владельца возвращён согласованный логотип варианта C. Для клиентского режима используйте **START_CLIENT_PREVIEW.bat** или `npm run preview`, не обычный npm start. Просмотр работает на отдельной БД с правами только чтения; оформление, ремонтные заявки, админка и служебные API заблокированы. Внешняя публикация разрешена, но пока заблокирована отсутствием рабочего SSH-доступа. Подробная инструкция и границы — [CLIENT_PREVIEW.md](CLIENT_PREVIEW.md).

После клонирования на Windows с Node.js 24.x:

```powershell
npm ci
npm run setup:local
npm run preview:setup
npm run build
npm run preview
```

Откройте http://localhost:3000. Предыдущий сервер на этом порту должен быть остановлен. Импортированы 41 товар и 67 реальных фотографий — проверенная выборка, а не весь ассортимент. Публичный GitHub-репозиторий содержит исходники: ссылка на него не заменяет размещение Node/PostgreSQL-приложения.

Ниже сохранена инструкция обычного режима разработки. Его 50 синтетических fixtures нужны для регрессионной проверки корзины и не показываются в клиентском режиме.

## Обычный режим на этом компьютере

Откройте **http://localhost:3000**. Приложение и отдельная PostgreSQL работают локально; адрес доступен только на этом компьютере.

После перезагрузки откройте `start.bat` в этой папке и оставьте терминал открытым. Скрипт запустит собственную локальную базу и сохранит записи. Уже работающий магазин второй раз не запускается.

Администрирование: **http://localhost:3000/admin**. Email: `admin@localhost.test`. Уникальный начальный пароль — в локальном файле `.state/admin-password.txt`. Сохраните его в менеджере паролей и удалите файл передачи после сохранения. В БД хранится только scrypt-хеш. Пароль, .env и .state в исходный архив не включены. Повторный setup не меняет существующего администратора.

## Архитектура

Вариант C уже содержал Node.js HTTP-сервер и JavaScript-интерфейс с маршрутизацией. Они сохранены без переписывания на Next.js. Сервер перенесён на TypeScript, SQLite заменена PostgreSQL через Prisma, валидация — Zod. Исходные CSS сохранены; дополнения — `public/app-additions.css`. Это приложение с серверными API, не один HTML-файл.

Версии приёмки: Node.js 24.22.0, PostgreSQL 18.6, Prisma 7.10.1, TypeScript 5.9.3. Требуется Node.js **24.x**.

## Установка из архива на Windows

Установите Node.js 24.x, распакуйте исходники и откройте PowerShell в папке проекта:

```powershell
npm ci
npm run setup:local
npm run build
npm start
```

Первый setup создаёт приватный .env со случайным паролем БД. Скрипт скачивает официальные Windows-бинарники PostgreSQL, сверяет SHA256 с опубликованной контрольной суммой EDB, создаёт отдельный кластер `.state/postgres-data` и запускает его на 127.0.0.1:55440. Нужны сеть и свободное место. Установленный runtime повторно не скачивается. Системные службы PostgreSQL не заменяются.

На текущем компьютере launcher также использует настроенный Node 24 из `.state/node-path.txt`. Этот локальный путь не переносится в архив: на другом компьютере нужен Node 24 в PATH.

Остановка приложения — Ctrl+C. После неё собственную native PostgreSQL можно остановить через `npm run db:stop`. Не удаляйте .state, если нужны заказы, заявки, корзины и администратор. Повторный seed не сбрасывает цены/остатки.

## Внешняя PostgreSQL и Docker

compose.yaml подготовлен как альтернативный запуск PostgreSQL. Docker на проверенном компьютере отсутствует: **запуск через Docker не проверен**. Приёмка выполнена на native PostgreSQL.

Для внешней БД создайте .env по .env.example и используйте hostname **localhost** вместо 127.0.0.1, чтобы не включать управление native-кластером. В Docker POSTGRES_PASSWORD и пароль DATABASE_URL должны совпадать. Native-кластер и Docker не должны одновременно занимать порт 55440.

```sh
docker compose up -d db
npm ci
npm run setup:local
npm run build
npm start
```

Форма URL: `postgresql://kruga_app:YOUR_PASSWORD@localhost:55440/kruga_shop`. Специальные символы пароля требуют URL-кодирования. Для macOS/Linux нужен установленный PostgreSQL или Docker; `bash start.sh` запускает настроенное приложение.

## Что работает

- / — подбор бренда/модели, категории, популярные товары, ремонт, доставка и контакты.
- /catalog — поиск названия/артикула; совместные фильтры бренда, модели, категории, наличия и цены; сортировки и пагинация.
- /product/[slug] — характеристики, совместимость, количество, остаток, изображения и похожие товары. Несуществующий slug возвращает HTTP 404.
- /cart — серверная корзина: количество, удаление, очистка, сохранение после обновления в том же браузере.
- /checkout — необязательный email, условный адрес, согласие, серверная перепроверка цены/остатка, сохранение заказа и позиций, идемпотентность.
- /orders/[id] — подтверждение только для сессии, создавшей заказ.
- /repair — сохранение заявки и номера без обещания реального обратного звонка.
- /admin — вход, создание/редактирование товара, цена/остаток/совместимость, заказы и заявки, смена статуса заказа, выход.
- /privacy, /delivery — информация о локальной обработке и получении заказа.

Суммы хранятся и считаются в целых копейках. Оформление использует транзакцию и блокировку строк, перечитывает цены/остатки и не доверяет браузерному итогу. Повтор того же ключа возвращает существующий заказ; другой запрос с тем же ключом — конфликт. Конкурентная покупка последнего остатка не создаёт две продажи.

## Данные и ограничения

Seed создаёт **50 синтетических товаров**, 4 бренда и явно заданную совместимость. Это не подтверждённый ассортимент 4kruga.ru. После браузерной проверки в текущей БД дополнительно есть один созданный через админку товар и синтетические заказ/заявка.

`public/logo.png` сохранён без изменений. В интерфейс возвращён ранее согласованный public/logo-transparent.svg без нового рисунка. Скачанный логотип действующего сайта также сохранён в public/media/4kruga/logo-original.png, но не используется в шапке. В клиентском режиме показываются реальные локальные фотографии товаров; старые заглушки сохраняются только для тестовых данных обычного режима.

Контакты действующего магазина берутся из prisma/official-catalog.json через src/config.ts. Заказы/ремонт обычного режима сохраняются только локально, а в CLIENT_PREVIEW заблокированы. Реальной оплаты, передачи магазину, рассылок, расчёта доставки и CMS-интеграции нет. Статус «Отменён» не возвращает остаток автоматически: его корректирует администратор. Заказы/ремонт в админке ограничены последними 200 записями. Аккаунты покупателей не реализованы.

## Безопасность и хранение

Сервер слушает только 127.0.0.1. Записи защищены Origin/Host, админ-API — отдельной HttpOnly/SameSite=Strict сессией. В БД — хеши токенов и scrypt-хеши паролей. Есть rate limit, лимит JSON 64 КБ, безопасные ошибки и CSP. Secure cookie не включён для локального HTTP; публичный запуск требует отдельной HTTPS-конфигурации и приёмки.

Исходники, .env и БД не раздаются статическим сервером. Логи приложения не печатают тела заказов и пароли. Не вводите реальные клиентские данные без согласованного хранения/удаления. В архив не входят .env, .state, данные БД, зависимости и сборка.

Для резервной копии используйте pg_dump с приватными параметрами окружения. Копирование работающей папки кластера не заменяет согласованную резервную копию. Восстановление бэкапа и перенос на другую ОС отдельно не проверялись.

```sh

npm run build
npm test
npm audit
```

Тесты обычного режима используют отдельную БД из .env.test.local с именем, начинающимся на kruga_shop_test. Она очищается перед тестом. Preview-тесты используют отдельную kruga_shop_preview_test, созданную npm run preview:setup, и параметры из .env.preview-test.local. Выполните оба setup перед npm test. Рабочая kruga_shop не используется для разрушительных проверок. Native setup создаёт тестовые роли/БД автоматически. Для внешней PostgreSQL создайте их отдельно.
